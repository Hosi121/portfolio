# Portfolio

Astroで日英のポートフォリオとブログを静的生成します。記事は手元で開いたブログのページ上で直接編集できます。

## 記事を書く

Node.js 24を使用します。初回は `npm ci`、以降は次のコマンドで起動します。

```sh
npm run dev
```

1. http://localhost:4321/blog/ を開き、「記事を書く」を選びます。
2. 記事と同じ背景・文字組みのまま、タイトルと本文を入力します。初回だけURL名を英数字で指定します。
3. 必要に応じて見出し・太字・リンク・画像などを挿入し、「保存」を押します（Ctrl/Cmd+Sでも保存できます）。
4. 「閲覧に戻る」で記事の見た目を確認できます。既存記事はそのページの「編集」から書き直せます。

編集時は文字数と推定読了時間をリアルタイム表示し、記事ページにも同じ情報を表示します。本文内の見出し・コード・脚注を含め、タイトル・概要・空白・改行・装飾記号・画像の代替テキスト・脚注番号は除きます。絵文字や結合文字は見た目の1文字として数えます。読了時間は毎分500文字で切り上げる目安で、空の記事は0分です。

脚注は本文のカーソル位置でツールバーの「脚注」を押し、本文の下に現れる欄に注釈を書きます。番号は本文順に自動で振り直します。「脚注を外す」で番号と注釈を外せます。閲覧時は番号から注釈へ、↩から本文へ戻れます。注釈はプレーンテキストで、記事ファイルの `footnotes` 欄に保存します。

新規作成の直接リンク：http://localhost:4321/blog/new

表示サンプル：http://localhost:4321/portfolio/blog/sample/hoge （ローカル限定。本文・見出し・画像の見た目を確認できます）

新規記事は下書きです。下書きは手元の一覧・本文にだけ表示され、本番の一覧・本文・RSS・サイトマップには含まれません。日付は表示と並び順のための値で、予約公開ではありません。

保存先は `src/content/posts/*.mdoc`（MarkdownベースのMarkdoc）、画像は `src/assets/posts/` です。保存だけでは公開されません。公開リポジトリにpushした原稿のソースはGitHubで読めるため、非公開の原稿はpushしないでください。

入力中の文章はタブ内にも一時保存し、再読み込み時に復元します。これは記事ファイルへの保存とは別です。「手元に保存しました」がファイル保存完了の目印です。別のタブやファイルで記事が更新された場合は上書きせずエラーを表示します。エラーの下にある「保存済みの記事を別タブで開く」で最新の内容を開き、必要な入力を移してください。元のタブの文章は残ります。

編集画面はTiptapを使った独自UIです。Markdocの独自タグやHTMLを含む既存記事は、内容を壊さないよう画面上での編集を止めます。そうした記事はファイルで編集してください。画像を挿入すると画像ファイルはすぐに保存され、本文の保存前にページを離れると未使用の画像が残る場合があります。

編集途中に画面が切り替わらないよう自動リロードを無効にしています。別タブのプレビューは保存後に手動で再読み込みしてください。設定ファイル変更後は開発サーバーを起動し直してください。

## 公開

```sh
npm run build
npm run preview
```

http://localhost:4321/portfolio/ で公開用ビルドを確認できます（開発サーバーが同じポートで動いていれば表示された別ポートを使用）。`dist/` が公開物です。編集UI・新規作成ページ・保存APIはローカル開発時のみ有効です。

GitHub Pagesの Settings → Pages → Source を **GitHub Actions** に設定し、mainへpushすると `.github/workflows/deploy.yml` がビルド・公開します。公開前に下書きをオフにして保存し、記事と画像を一緒にコミットしてください。

ローカルでは `/`、本番では既存の `/portfolio/` を使います。英語版の既存URL `/portfolio/en.html` はビルド後の処理で維持します。HTMLファイルを直接開く旧運用から、開発サーバーを使う運用に変わりました。

この環境では開発サーバーはバックグラウンドで起動します。終了は `npx astro dev stop`、ログは `npx astro dev logs` です。ターミナルの手前に起動した場合は Ctrl+C でも終了できます。ビルドと開発サーバーは同時に実行しないでください。

## 構成と編集

- `src/pages/index.astro` / `src/pages/en.html.astro`：プロフィール、研究・活動記録。内容の更新は両言語に反映します。
- `public/styles.css`：生成りの背景、システムフォント、通常体の名前・見出し、スマートフォン対応。
- `public/garden.js`：Canvas 2D による花束・小鳥の ASCII 表現と、油絵風の筆跡。
- `public/og-garden.png`：リンク共有用の花束・小鳥の画像（1200 × 630 px）。日英共通で Open Graph / X のカードに指定し、通常のページ表示では読み込みません。
- レジュメは CV / PDF リンクから開けます。

冒頭の紹介文は、人と計算機の関わりを軸に、新しいものを作ることと、既存の複雑なシステムをより速く、大きく、安全にする姿勢をまとめています。「現在取り組んでいること」（英語では `What I'm working on`）に「推論高速化 / 物質と計算」を掲載し、その直下に研究関心を並べます。

画面構成は [kawak.in](https://kawak.in/)、文字の質感は [Dither Canvas](https://www.obsidianui.dev/docs/dither-canvas) を参考にしています。
花束を中心に、花の種類・配置・色、小鳥の向き・数・位置をページ読み込みごとに決めます。サイズ変更やポインター操作で構図は変わりません。

描画は初期化後、ポインター操作などがあるときだけ行います。常時描画するループ、動画、外部フォント、外部ライブラリは使用していません。
「動きを減らす」設定ではポインターによる変形を止めます。JavaScript 無効時も文字絵の代替表示、本文、実績の開閉、日英の切り替えが使えます。

共有画像は既存の `garden.js` の描画と名前を Chromium で静止画にしたものです。共有時はこの固定画像を使用し、サイト内の構図は引き続き毎回変わります。画像 URL・形式・幅・高さ・言語ごとの代替テキストを HTML のメタデータに記載するため、共有先で JavaScript を実行する必要はありません。仕様は [Open Graph](https://ogp.me/#structured) を参照してください。共有先が古いカードをキャッシュしている場合は、そのサービスでの再取得後に更新されます。

実績の開閉には HTML の `details` / `summary` を使用しています。既存の見出しへの URL は該当項目を開き、印刷時は全項目を展開します。
見出しを押すと 1 px 沈む反応を付け、[Vibration API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate) 対応端末では開閉操作時に 12 ms の振動を要求します。連続した振動は 100 ms 間隔に制限します。URL による展開や印刷では振動せず、「動きを減らす」設定では振動・押下時の動きともに停止します。iPhone / Safari など API 非対応環境では見た目の反応のみで、追加ライブラリや音声は使いません。実際の振動は端末のハードウェア・OS 設定に依存し、実機での触感は未確認です。
研究実績の「ポスター発表」「記事・解説」はそれぞれ初期状態で折りたたみます。NDSS 2025 の発表は「ポスター発表」に掲載し、タイトルに `(poster)` を付けます。採択実績では「助成・事業採択／チャレンジ」をフェローシップより先に掲載します。
研究・採択・受賞の補助リンク（details、poster、ACM DL、Official、最終審査会）は省略し、受賞のプレスリリース・新聞記事へのリンクは残します。母数等が不明な欄は表示しません。
受賞経験の「その他の受賞」はビジネスコンテストの下に配置し、テクノ愛2025・浜松市ウェルビーイングアイディアコンテスト・静大アイデアソン／データソン2025・COG 2024 の4件を初期状態では折りたたみます。
運営・管理経験は現在の活動を `開始年–：活動名` で先に掲載し、国際人工知能オリンピック日本委員会（JOAI委員会、2026年から）を先頭に、CPC（2024年から）を続けます。補足の小さい文字や外部リンクは省略します。「遍歴」に `2024–2025：ANCHOR（神経科学や認知科学の読書会を主宰）`、`2025：ChoiAca（研究イベントの情報集約サイトを運営）`、`2024–2026：IYNA (advisor)` を折りたたみます。

プレプリントの被引用数は [Semantic Scholar の論文ページ](https://www.semanticscholar.org/paper/6d885c9cfcb4643d9ead13f6b92b759def0002f6) にリンクしています。2026-09-23 に [公式 API](https://api.semanticscholar.org/graph/v1/paper/ARXIV:2503.02142?fields=title,url,citationCount) の `citationCount` で9件を確認しました。取得時点の静的な値を日英に記載し、実行時の API 通信は追加していません。

## OSS の掲載方針

「推論高速化」の枠内で「マージ済み」「提案中」の順に分け、各項目は `repo名 ☆ スター数：説明 [PR #番号]` の1行形式とし、PR に直接リンクします。マージ日時は掲載しません。日本語では「逆畳み込み」、英語では “transposed convolution” と表記します。

PR の状態とスター数は編集時に GitHub から取得する静的な記録です。実行時の GitHub API 呼び出しはありません。
ESP-DL #332 は GitHub 上では closed ですが、[メンテナーによる内部 GitLab でのマージ報告](https://github.com/espressif/esp-dl/pull/332#issuecomment-5658820520) を根拠にマージ済みに分類しています。

## 既存HTML版での確認記録

ローカル Chromium / Playwright で、320・390・768・1440 px の日英表示、キーボードによる開閉、JavaScript 無効時、動きを減らす設定、ランダムな再描画、見出し URL、印刷後の開閉状態、ファイルの直接表示を確認しています。本文・リンクと OSS の分類も確認済みです。
振動 API の呼び出しを記録するブラウザ確認では、入れ子の項目で二重発火しないこと、連打の抑制、キーボード操作、URL・印刷・プログラムによる開閉で振動しないこと、動きを減らす設定、API の未対応・拒否・例外時にも通常の開閉が動くことを確認しています。

日本語ページの初期読み込み対象は HTML / CSS / JS の3ファイルで、非圧縮の合計は 51,926 bytes です。変更前（`76f4f68`）は HTML / CSS / WebP の 93,291 bytes でした。初期表示からプロフィール画像を外した変更を含みます。PDF、リンク先の画像、HTTP ヘッダーは比較対象に含めません。現在の3ファイルを個別に gzip 圧縮した合計は 15,092 bytes ですが、実際の転送量は配信サーバーの圧縮設定に依存します。
